Overview

workctl is a Rust control plane for delegated software-development tasks.

It records task intent in workd, lets workers prepare execution contexts, and runs agent harnesses such as OpenCode inside explicit executor runtimes.

The control-plane shape

workctl CLI -> workd control plane -> worker loops
                                  -> prepared execution contexts
                                  -> agent harnesses inside executor runtimes

The CLI captures human intent. The daemon owns durable state. Workers claim tasks, materialize the requested context, run a harness, then report outputs, artifacts, records, and cleanup-relevant history.

Core concepts

Task

The central object: intent, context requirements, ownership, sessions, outputs, artifacts, cleanup policy, and handoff history.

Harness axis

The agent protocol or coding loop, currently including opencode-acp and a CI-friendly fake-summary harness.

Executor axis

The runtime boundary. The current implementation exposes local-devshell; the model leaves room for containers, isolates, VMs, or Kubernetes.

Context prep

Workers clone or mount repos, apply checkout hints, write prompts and manifests, redirect HOME/XDG/temp paths, and expose artifact locations.

Records

A replayable stream captures state changes, claims, prepared contexts, artifacts, outputs, failures, and other task history.

Artifacts and outputs

Large files such as context manifests, protocol logs, summaries, and repo diffs are artifact-backed; review results are stored as durable outputs.

A typical flow

01 Submit intent

A user submits a title, intent, repo list, optional checkout, harness, and executor through workctl task submit.

02 Worker claims

workd stores the task, a worker loop claims it, and state records make ownership visible.

03 Prepare context

The context preparer creates a task workspace with repos, generated prompt material, redirected process paths, and a context manifest.

04 Run harness

The selected harness runs inside the executor runtime; OpenCode ACP streams agent text and tool calls back through artifact content.

05 Record outputs

Summaries, protocol logs, context manifests, and repo diffs become outputs, records, and artifacts available through the task API.

06 Review and hand off

Humans inspect task outputs, task records, task artifacts, task review, or raw task diff before accepting, publishing, or cleaning up.
